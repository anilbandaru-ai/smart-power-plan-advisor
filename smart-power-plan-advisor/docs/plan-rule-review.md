# Plan-by-plan calculation review

Reviewed September 12, 2026 against the saved catalog: 43 distinct TXU API offers and 20 ordinary PDF plan records (22 source files). The same TXU offers appear in both cached ZIPs. This review does not refresh or certify live tariffs.

## Findings that determine the rules

- **Source conflicts matter.** Free Pass 12’s linked EFL has different rates and 7/9 free days with per-kWh delivery waived, while its cached API advertises seven days. The API illustration keeps its own rates and editable assumptions; the EFL version is not merged into it.
- **Zero is sometimes a placeholder.** Several TXU offers publish zero base/delivery/energy components while showing nonzero average prices. Their benchmarks can support illustrations, but the component list cannot support a complete bill.
- **Duplicate energy rates lack applicability labels.** Value Edge, Solar Saver, Saver’s Choice and e-Saver have multiple rates. Choosing the cheapest or first rate is unjustified; use benchmark illustrations pending clarification.
- **Credits create discontinuities.** For reliable PDF thresholds, add known credits back before interpolating benchmark bills and apply the threshold afterward. Unspecified API credit schedules remain benchmark-only.
- **Free periods differ by provider.** Reliant Overnight and Flextra waive both energy and per-kWh delivery; fixed delivery remains. Their same-document 32% sample shares are defaults, not the customer’s usage.
- **Green energy is not export compensation.** Solar Club and Solar Days supply renewable energy without requiring panels. Only Solar Buyback scenarios use explicitly assumed exports and compensation.
- **A published average can hide assumptions.** Benchmark illustrations do not prove eligibility, threshold behavior, seasonal allocation, fees, or future rates. Their adjustment control is a sensitivity scenario, not a confidence interval.

## Versioning and implementation

Every row binds to a full source fingerprint in [plan_reviews.json](../backend/catalog/plan_reviews.json). PDF fingerprints include document hashes; API fingerprints include the complete offer. Changed terms invalidate the reviewed profile and revert to a review-needed benchmark illustration if valid examples remain. Calculations use SQLite/API data only; no runtime PDF reads occur.

Reviewed profiles are illustrations, not approvals. The original pricing exclusions are retained. At this snapshot, 9 PDF and 2 TXU records qualify for the existing calculated ranking; the other 52 records have separate rough methods. A hidden offer remains hypothetical. Expired TXU snapshots cannot supply estimates.

## Future providers

1. Implement an ingestion adapter for the shared catalog contract, retaining source identity, full raw/extracted data, provenance, price examples and existing eligibility validation.
2. Review the source and bind a profile to its fingerprint. Use the existing method schema: benchmark, flat/threshold, marginal tier, free usage, seasonal discount/credit, solar or reward. The calculator contains no provider-name branches.
3. Supply explicit recurring rates in cents/kWh and USD/month, conditional credit bounds, notes and editable defaults. Record unavailable terms; do not invent a rate from the plan name or select among unlabeled duplicate rates.
4. Test independent bills at benchmarks and each boundary, zero usage, variable/short horizons, source changes and malformed inputs. Exact ranking requires a separate reviewed validated-ingestion change; adding a rough profile never grants eligibility.
